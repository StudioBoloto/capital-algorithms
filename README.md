# Алгоритмы Столицы

**Система обнаружения препятствий в тоннеле метро**

Проект команды «Алгоритмы Столицы» для кейса Департамента транспорта Москвы. Решение
обрабатывает поток `sensor_msgs/PointCloud2` от 128-канального лидара и
формирует причинную тревогу, если подтверждённый объект находится в свободном
габарите перед поездом.

Контур рассчитан на Ubuntu 22.04, ROS 2 Humble, Docker и NVIDIA GPU. Для работы
не требуются внешняя calibration map, TF или odometry.

## Результат на данных организаторов

- потоково обработаны все 2 488 кадров из шести ROS 2 bag;
- на 2 287 инфраструктурных кадрах получено 0 alarm-кадров;
- событие с человеком в `doubleT_obstacle` обнаружено;
- 43 из 45 размеченных кадров Person совпали с итоговой тревогой;
- bounded real replay на NVIDIA Tesla T4 работал с частотой 9,9–10,4 Гц.

В данных нет полной покадровой 3D-разметки. Поэтому эти значения являются
proxy-наблюдениями, а не precision/recall всего датасета.

## Быстрый запуск reference-прототипа

```bash
docker build -t capital-algorithms:prototype .
docker run --rm capital-algorithms:prototype
```

Прототип читает небольшой поток XYZ-кадров, выделяет компактную занятость в
габарите и формирует тревогу после причинного подтверждения в двух кадрах. Он
показывает базовую гипотезу и формат исполнения. Production ROS 2-контур,
проверенный на реальных PointCloud2, содержит дополнительные ступени подавления
инфраструктуры и нейросетевой проверки.

GitHub Actions повторяет обе Python-проверки, собирает Dockerfile и запускает
получившийся контейнер при каждом push.

Публичный пакет первого этапа показывает интеграционный контракт и измеренные
результаты. Обучающие данные, checkpoint, точные конфигурации обучения и
внутренние исследовательские материалы в него не входят.
